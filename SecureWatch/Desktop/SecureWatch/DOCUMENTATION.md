# Mini SOC Lab — SIEM-Based Threat Detection & Incident Response System

This is a complete, production-ready project simulating a real-world Security Operations Center (SOC) environment, aligned with SOC Analyst responsibilities.

## Setup Guide (Step-by-Step)

### Prerequisites
* Python 3.9+
* Pip (Python package manager)

### Installation

1. **Navigate to the backend directory**
   ```bash
   cd backend
   ```

2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

3. **Start the application**
   ```bash
   python app.py
   ```
   *(This will start the backend Flask server and serve the frontend files automatically.)*

4. **Access the interface**
   * Open your browser and go to: `http://localhost:5000`
   * **Login credentials:** 
     * Default User: `admin` / Password: `password123`
     * (Defined via the `db.py` initialization)

5. **Load Sample Logs (First Run)**
   * On the dashboard, click **"Load Sample Logs"** in the top right to ingest basic logs and test detections.

## SOC Workflow Explanation

1. **Log Collection & Normalization:**
   Logs from various sources (Linux, Apache/Nginx, Firewalls) are ingested into the system. The `log_collector` normalizes these into a structured JSON schema, storing them in the `logs` table.

2. **Threat Detection (SIEM Logic):**
   The `threat_detector` continuously checks incoming logs against static rules inspired by MITRE ATT&CK (e.g., Brute Force T1110, Port Scanning T1046).

3. **Event Correlation & Threat Intelligence:**
   The `correlator` identifies complex, multi-stage attacks by tying together multiple logs (e.g., multiple failed logins followed by a success). Logs are additionally cross-referenced against known malicious IPs/domains in the `threat_intel` module to flag IOC matches.

4. **Alerting & Incident Response (SOAR):**
   Detections generate **Alerts**. Analysts review these in the Alert Dashboard. High-value alerts or persistent threats are escalated into **Incidents** within the Incident Response module, which includes workflow states (`TRIAGE`, `INVESTIGATE`, `RESPOND`, `CLOSED`), automated timelines, and analyst notes.

5. **Hunting & Reporting:**
   Analysts can proactively search logs for anomalies using predefined or custom SQL queries in the **Threat Hunter** module. Status and summaries of alerts and incidents are generated periodically via the **Reports** module.

## Mapping to SOC Analyst Job Description

| SOC Analyst Skill/Function | Implementation in Mini SOC Lab |
| :--- | :--- |
| **Log Analysis** | Normalization of Linux, Web, and Firewall logs; filtering and searching through the Log Viewer. |
| **SIEM Rule Creation** | The `threat_detector` engine uses MITRE-mapped logic tests simulating typical SIEM alerts. |
| **Threat Intelligence** | `threat_intel.py` matches IPs and domains against bundled JSON IOC feeds in real-time. |
| **Threat Hunting** | Proactive search interface with predefined queries (e.g., Rare SSH Logins, Failed Su Attempts) and custom SQL. |
| **Incident Response** | Ticket tracking system complete with SLA states, ownership assignment, and escalation checks. |
| **Security Reporting** | Automated Generation of Daily and Weekly compliance-style summaries via HTML/PDF. |

## API Documentation

The backend provides a RESTful API serving both data points and controlling system states.

### `POST /api/auth/login`
**Description:** Authenticate users and acquire a session token.

### `GET /api/logs`
**Description:** Retrieve and filter ingested logs.
**Params:** `type` (optional), `limit` 

### `POST /api/logs/ingest`
**Description:** Send new logs to the collection pipeline.
**Payload:** `{"lines": ["..."], "source_type": "linux|web|firewall"}`

### `GET /api/alerts`
**Description:** Fetch alerts generated by the detection engine.
**Params:** `status` (OPEN|ACK|CLOSED), `limit`

### `PATCH /api/alerts/<id>/status`
**Description:** Update an alert's status.
**Payload:** `{"status": "ACK|CLOSED"}`

### `GET /api/incidents`
**Description:** Retrieve active and closed security incidents.

### `POST /api/incidents`
**Description:** Create a new incident case.
**Payload:** `{"title": "...", "severity": "HIGH", "alert_ids": [...]}`

### `POST /api/incidents/<id>/transition`
**Description:** Change an incident's state (e.g., TRIAGE -> INVESTIGATE).

### `POST /api/simulate`
**Description:** Run a simulated attack (Brute Force, Port Scan, Phishing) to generate logs and alerts.
**Payload:** `{"type": "brute_force"}`

### `GET /api/reports`
**Description:** Fetch generated daily/weekly reports.
